# Telemost Web: поверхность темизации (исследование)

Дата сбора всех данных: 2026-09-22. Все факты ниже получены из публичных ассетов,
если не указано иное. Контекст репозитория: текущий движок — десктопный
`telemost-start.exe`, накладывающий тему поверх Телемоста без правки его файлов;
эта заметка исследует **веб-версию** как новую цель.

## 1. Где живёт веб-клиент и его ассеты (ПРОВЕРЕНО)

- `https://telemost.yandex.ru/` отдаёт SPA-оболочку (сохранена локально как `research_notes/Полная перекраска интерфейса Телемоста/evidence/telemost_home.html`, 98 686 байт).
- Все статические ассеты версионируются и лежат на yastatic:
  `https://yastatic.net/s3/chat-static/telemessenger/_/211.2.0/web/`
  - `app.js` (загрузчик)
  - `ui.css` — единый CSS-бандл, ~1 889 891 байт (сохранён как `research_notes/Полная перекраска интерфейса Телемоста/evidence/telemost_ui.css`)
  - `ui.chunk.js` — основной JS-бандл, ~1 115 618 байт (сохранён как `research_notes/Полная перекраска интерфейса Телемоста/evidence/telemost_ui_chunk.js`)
- Версия в пути (`211.2.0`) меняется при деплоях Яндекса → любой хардкод версионного URL должен перепроверяться; имена файлов внутри версии (`ui.css` и т.д.) стабильны.
- Страница встречи имеет вид `https://telemost.yandex.ru/j/{код}` (подтверждается сторонним кодом, см. §6.2).

DOM оболочки (из `research_notes/Полная перекраска интерфейса Телемоста/evidence/telemost_home.html`):
- `<html lang="ru" class="browser desktop">`
- `<body class="ym-hide-content desktop">`
- `<div id="root">` — точка монтирования всего приложения.

## 2. Модель стилей: токены дизайн-системы Orb (ПРОВЕРЕНО)

### 2.1. Три уровня CSS custom properties

Бандл `ui.css` минифицирован (самая длинная строка ~522 404 символа), но структура токенов читается однозначно:

1. **Палитра (сырые цвета)** — определены на `:root`:
   - `--orb-color-cool-gray-100:#edeff0`, `--orb-color-cool-gray-1000/1100/950/900…` (шкала серого, включая тёмные ступени),
   - `--orb-color-ya-telemost-700:#0bb552` — **фирменный зелёный Телемоста**,
   - `--orb-color-ya-messenger-400/500/600/700` (брендовая шкала Мессенджера), `--orb-color-white`, `--orb-color-black-alpha-700`, `…-dark-alpha-…` и т.п.
2. **Семантические токены** — определены на `:root` через `var()` от палитры:
   - текст: `--orb-text-primary`, `--orb-text-secondary`, `--orb-text-brand` (используются сотни раз; `--orb-text-primary` — самый частый цветовой токен);
   - поверхности: `--orb-surface-generic`, `--orb-surface-generic-medium`, `--orb-surface-brand`;
   - слои/тени: `--orb-elevation-sunken`, `--orb-elevation-base`, `--orb-elevation-risen`, `--orb-elevation-overlay`, `…-blurred`, `…-modal`;
   - типографика: `--orb-typo-body-font`, `…-heading-font`, размеры/кернинг;
   - отступы: `--spacing-4m`, `--spacing-6m` и т.п. (самые частые токены в бандле).
3. **Компонентные токены** — `--component-telemost-*` (например, `--component-telemost-feedback-star-selected-color:var(--orb-surface-brand)`), `--ui-card-contrast-box-shadow` и т.п.

### 2.2. Маркеры темы (стабильные переключатели)

Тема переключается **классами на `:root` (т.е. на `<html>`)**, не `data-атрибутами`:
- `.theme_light` — светлая;
- `.theme_dark` — тёмная;
- `.theme_auto` — авто (очевидно, реагирует на системную тему логикой в JS; сами `@media (prefers-color-scheme)` в `ui.css` **не найдены** — правило 0 совпадений).

Тёмная тема реализована как полный ремап семантических токенов на палитру тёмных ступеней:
```css
.theme_dark:root{
  --orb-elevation-sunken:var(--orb-color-cool-gray-1100);
  --orb-elevation-base:var(--orb-color-cool-gray-1000);
  --orb-elevation-risen:var(--orb-color-cool-gray-950);
  --orb-elevation-overlay:var(--orb-color-cool-gray-900);
  --orb-elevation-base-blurred:var(--orb-color-cool-gray-dark-alpha-900);
  --orb-elevation-overlay-blurred:var(--orb-color-cool-gray-dark-alpha-700);
  --orb-elevation-overlay-modal:var(--orb-color-black-alpha-700);
  --orb-surface-…:…;
}
```
(блок извлечён из `ui.css`; усечён в заметке, полный — в файле.)
Также встречаются `.theme_light .hljs …` — подсветка кода в чате.
Вывод: **достаточно переопределить палитру `--orb-color-*` на `:root` — обе темы и все компоненты перекрасятся каскадно.** Это главная точка входа для перекраски.

### 2.3. Прецедент бренд-переключателя (официальный паттерн Яндекса)

В `ui.css` есть готовый механизм «бренд-перемапливания» токенов, который Яндекс использует для своих сервисов на общем Orb-ките:
```css
.Orb-Brand_brand_telemost :root,
.brand_telemost :root,
:root.Orb-Brand_brand_telemost,
:root.brand_telemost {
  --orb-surface-brand:var(--orb-color-ya-telemost-700); /* #0bb552 */
  --orb-text-brand:var(--orb-color-ya-telemost-700);
}
```
(по умолчанию `--orb-surface-brand/--orb-text-brand` указывают на `--orb-color-ya-messenger-*`).
Это прямой прецедент: **ремап `--orb-*` на `:root` — штатный способ Яндекса менять фирменный цвет**, т.е. наш подход не борется с архитектурой, а повторяет её.
Зелёный = `--orb-color-ya-telemost-700:#0bb552`.

## 3. Имена классов: стабильность (ПРОВЕРЕНО)

Классы в `ui.css` **семантические, не хешированные** (нет CSS-modules-хешей):
- `yamb-*` — компоненты Телемоста (BEM): `.yamb-video-player`, `.yamb-video-viewer`, `.yamb-toast-container`, `.yamb-voice-action-panel-*`, `.yamb-upload-files-*`, `.yamb-url-preview`, `.yamb-threads-list-item`, `.yamb-user-bubble__name`, `.yamb-poll-answer-base`, `.yamb-warning-chat-bar` и т.д. (`yamb` = Yandex Messenger/Telemost-префикс; сотни уникальных блоков).
- `Orb-*` — компоненты UI-кита Орб: `.Orb-UserPicGroup`, `.Orb-Brand_brand_telemost` (PascalCase + BEM-модификаторы).
- Легаси Яндекса: `ym-*`, `.hljs`.
- Немного BEM `__`/`_` внутри `yamb-*`.

Риски: имена стабильны в рамках версии, но это внутренние имена Яндекса — могут меняться между релизами; поэтому опора на токены (§2) предпочтительнее опоры на классы. Классы нужны только точечных мест, куда токены не дотягиваются.

## 4. Границы и «некрасящиеся» поверхности

- **Shadow DOM: нет.** В `ui.chunk.js` — 0 совпадений `attachShadow`, 0 `shadowRoot`. Обычный каскад работает на всё дерево.
- **iframe: минимально.** В `ui.chunk.js` найдено 1 место создания `iframe` через `createElement`. Назначение (НЕТ ПРОВЕРКИ в рантайме) — вероятно, встраиваемые виджеты/шаринг; страница встречи в оболочке не использует видимых фреймов.
- **Видео/канвас**: видео участников рендерится через `<video>`/медиа-платформу (классы `.yamb-video-player`, `.yamb-video-viewer` существуют в CSS) — сами видеопотоки CSS не красятся; красятся только подложки/контейнеры вокруг. Детали (какие именно элементы, есть ли canvas) — НЕТ ПРОВЕРКИ без живой встречи (§5).
- Один `@media`-запрос на весь бандл (не тема; вероятно, печать/иное) — тема не зависит от медиазапросов.

## 5. Что НЕ ПРОВЕРЕНО без живой встречи (нужен аутентифицированный инспектаж)

1. DOM страницы `/j/{код}` внутри звонка: сетка плиток, панель управления, чат — реальный набор элементов и их классы в рантайме.
2. Какой класс темы реально висит на `<html>` после инициализации приложения (оболочка грузится светлой; выбор `theme_dark/auto` presumably делает приложение по настройкам пользователя).
3. Подгружаются ли дополнительные CSS-чанки на маршруте встречи (в оболочке зафиксированы только `ui.css`/`ui.chunk.js`/`app.js`).
4. Тип видеоплиток (`<video>` vs canvas), наличие iframe внутри звонка (шаринг экрана, презентации).
5. Инлайн-стили (`style="…"`), которые приложение ставит в рантайме: они могут перекрывать наши правила (встречаются в SPA; объём неизвестен).
6. Точный список компонентов, где цвет задан хардкодом (`#hex`/`rgb()` прямо в правиле, а не через `var(--…)`), — требует аудита (§6.3).
7. Greasy Fork (поиск скриптов по «telemost») вернул HTTP 403 — наличие/отсутствие готовых юзерстилей там НЕТ ПРОВЕРКИ; на userstyles.world стилей для Telemost **нет** (проверено 2026-09-22).

## 6. Публичные прецеденты и источники

### 6.1. Готовых тем/юзерстилей практически нет (ПРОВЕРЕНО)
- userstyles.world: «No user styles matching "telemost"» (2026-09-22).
- GitHub code search: `telemost.yandex.ru` и `chat-static/telemessenger` — ни одного юзерскрипта/юзерстиля; только серверный код.
- Вывод: публичных «готовых» тем Телемоста нет; мы делаем первопроходца. Это же значит, что нет и чужих граблей, на которые можно опереться.

### 6.2. Сторонний код, раскрывающий структуру (ПРОВЕРЕНО)
- Репозиторий `cacggghp/vk-turn-proxy` (GPL-3.0), файл `client/main.go` (~строка 1090): использует API Телемоста `https://cloud-api.yandex.ru/telemost_front/v2/telemost/conferences/https%3A%2F%2Ftelemost.yandex.ru%2Fj%2F{link}/connection` — подтверждает формат ссылок встреч `/j/{код}` и публичный API-фронт `cloud-api.yandex.ru/net/telemost-front/v2`. К темизации отношения не имеет, но подтверждает маршрутизацию веба.

### 6.3. Рекомендуемый рабочий процесс открытия цветов (отвечая на вопрос задачи)

1. **Закрепить версию ассетов** (записать `211.2.0`), скачать `ui.css` + все чанки (сохранены как исследовательские доказательства: `research_notes/Полная перекраска интерфейса Телемоста/evidence/telemost_ui.css`, `research_notes/Полная перекраска интерфейса Телемоста/evidence/telemost_ui_chunk.js`, `research_notes/Полная перекраска интерфейса Телемоста/evidence/telemost_home.html`).
2. **Инвентаризация токенов без запуска страницы**: выписать из `ui.css` все `--orb-color-*` (палитра), затем пары `:root{…}` vs `.theme_dark:root{…}` — дифф даёт полный список семантических токенов, которые нужно переопределить (~десятки имён вместо тысяч правил).
3. **Аудит хардкода**: в `ui.css` найти правила с литеральными цветами вне `var()` (`background*:/color:/fill:/stroke:` + `#[0-9a-f]{3,8}|rgba?\(`) — это точки, которые ремап токенов не покроет; под них писать точечные правила по классам `yamb-*`/`Orb-*`.
4. **Живой аудит в звонке** (закрывает §5): в DevTools снять снапшот `document.querySelectorAll('*')` → для каждого элемента `getComputedStyle` по `color`, `background-color`, `border-color`, `fill`, `stroke`, `box-shadow` → кластеризовать уникальные значения → каждое значение сопоставить либо токену (шаг 2), либо хардкоду (шаг 3), либо пометить как некрасящееся (видео/изображения). Это карта «каждый видимый цвет» без метода «залить страницу оверрайдами».
5. **Порядок оверрайдов**: один блок `:root{ --orb-color-*: … }` (и при необходимости `:root{ --orb-text-brand: … }` и т.п.) → затем точечные правила для хардкода из шага 3 → инлайн-стили при необходимости бить `!important` или рантайм-наблюдателем (MutationObserver), если приложение их переставляет (НЕ ПРОВЕРЕНО).

## 7. Итоговые ответы на ключевые вопросы

- **Что раскрывает модель стилей?** Публичный версионируемый бандл `ui.css` на yastatic + оболочка `telemost.yandex.ru`. Этого достаточно, чтобы полностью описать токены и темы без входа в аккаунт.
- **Стабильные CSS-переменные?** Да: двухуровневая система `--orb-color-*` → `--orb-*`/`--component-telemost-*`, определённая на `:root`; тёмная тема — переопределением на `.theme_dark:root`.
- **Стабильность классов?** Семантические (`yamb-*`, `Orb-*`, `ym-*`), не хешированные; стабильны в рамках версии, между релизами не гарантированы.
- **Маркеры темы?** Классы `theme_light`/`theme_dark`/`theme_auto` на `<html>`.
- **Shadow DOM/iframe/динамический рендеринг?** Shadow DOM отсутствует; 1 место создания iframe; приложение — SPA, весь контент рендерится в `#root` (инлайн-стили в рантайме — риск, не проверен).
- **Какие контейнеры/состояния требуют явной обработки?** Оценочно по токенам: фоны (`--orb-elevation-*`, `--orb-surface-*`), текст (`--orb-text-*`), брендовые акценты (`--orb-surface-brand/--orb-text-brand` = зелёный `#0bb552`), тени/оверлеи (`--ui-card-contrast-box-shadow`, `…-modal`), плюс точечный хардкод из аудита; детали внутри звонка — НЕ ПРОВЕРЕНО.
- **Что нельзя проверить без живой встречи?** Перечислено в §5.
- **Практический процесс открытия цветов?** §6.3 (сначала токены офлайн, потом точечный хардкод, потом computed-color аудит в живом звонке).
